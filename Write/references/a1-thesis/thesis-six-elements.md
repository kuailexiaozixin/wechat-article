# A1 立意：研究性专业文章的六要素

本技能只服务一种体裁：**面向财务、税务、法律、金融、经济领域的研究性专业文章**。
读者是同行（财会人员、税务干部、律师、投行与研究员、监管人员），不是泛读者。
他们读文章是为了拿走一个可复用的判断，所以文章的成败在动笔之前就定了——**你有没有一个说得清的结论**。

A1 的唯一交付物是 `thesis.json`，出口判据是六要素齐备且结论带判断。
这一步之后，A2 的结构、A3 的素材、A4 的逻辑图、A5 的行文全部从 `thesis.json` 派生，
改动立意就要回退重跑后面四步，所以宁可在这一步多花时间。

生成骨架与校验：

```bash
python Write/references/a1-thesis/scripts/thesis_check.py init -o thesis.json
python Write/references/a1-thesis/scripts/thesis_check.py check thesis.json
```

## 一、先定体裁分类（`category`）

四类，只能选一类。选错类会让结构跟着错（案例评析文章用政策研究的框架写，读者会觉得你在绕）。

| 取值 | 适合什么 | 读者的期待 | 结构倾向（见 A2） |
|---|---|---|---|
| `政策解读` | 新规出台、修订、口径变化 | 变了什么、影响谁、怎么执行 | 背景 → 适用范围 → 实务指引 → 风险提示 |
| `理论分析` | 概念争议、原则冲突、体系定位 | 你的观点与论证链 | 问题提出 → 文献对话 → 分析 → 结论 |
| `案例分析` | 判决、处罚、重组、争议解决 | 从具体事实里能抽出什么规则 | 案情 → 多角度分析 → 防控建议 |
| `操作指引` | 落地执行、流程、判断标准 | 一步一步怎么做、哪里会错 | 痛点 → 合规路径 → 操作清单 |

跨两类的题目先拆：一篇只写一类，另一类另起一篇。混写是研究性文章最常见的失败原因——
它不是"覆盖面更全"，是"两个都没写透"。

## 二、研究领域与研究对象（`discipline` / `field` / `object`）

- `discipline`：正文所属领域，五选一——`财务`、`税务`、`法律`、`金融`、`经济`。跨领域的题目选**主要论证依据所在**的那一个（会计处理之争的落点在准则，就选财务，不选法律）。
- `field`：研究领域，写到二级学科或业务条线一层，例如「财务会计领域」「增值税征管」「证券虚假陈述民事责任」「商业银行资本充足监管」。
- `object`：研究对象，必须是**一个可以被指认的东西**，不是一句口号。判断办法：能补进"本文研究____的___"这个句式而不别扭。

| 不合格 | 为什么 | 合格 |
|---|---|---|
| 企业财税管理 | 太大，没有边界 | 研发过程中形成产品对外销售的会计处理 |
| 税收风险 | 是结果不是对象 | 跨期业务增值税纳税义务发生时点的判断 |
| 新收入准则 | 是一部准则不是问题 | 新收入准则下时段法履约进度的计量 |

## 三、核心问题（`question`）

一篇研究性文章只有一个核心问题，写成**一个问句**，且必须是这一篇能回答的。

写法要求：

1. 用疑问形式收尾：「如何处理」「如何认定」「是否构成」「能否适用」「应当由谁承担」「差异在哪里」。
2. 问题里要带**限定条件**（行业、交易形态、时点、主体身份）。少了限定，答案就只能写原则。
3. 不要把"是什么、为什么、怎么办"三个问题都塞进一句。

好问题的检验办法：把问题拿给同行看，他能不能立刻说出"这题有个争点"。说不出来，说明问题太大或者太陈旧。

## 四、研究目的与研究意义（`purpose` / `significance`）

- `purpose`：回答核心问题之后，**读者能拿去做什么**。写成动作，不写"加深理解"。
- `significance`：这个问题为什么值得回答。研究性文章的意义要落到**不同主体各自得到什么**，至少覆盖两类主体，因为财税法律问题的意义天生是分配性的：

| 主体类型 | 意义的落点 |
|---|---|
| 企业/纳税人 | 合规成本、税负、报表结果、诉讼风险 |
| 监管/征管机关 | 口径统一、执法一致性、征管效率 |
| 投资者/债权人 | 信息可比、定价、契约执行 |
| 行业/市场 | 交易结构选择、竞争中性 |
| 规则体系本身 | 填补漏洞、消除冲突、衔接国际准则 |

只写"具有重要意义""有助于高质量发展"的，等于没写意义——这类表述是空洞评价词，`check` 会拦。

## 五、研究结论（`claim`）——本阶段最关键的一个字段

结论必须**带判断**，具体到读者能照着做或照着反驳。四类不合格与对应的修法：

| 不合格类型 | 例子 | 修法 |
|---|---|---|
| 笼统 | 企业应当规范研发支出的会计处理 | 说出区分标准、科目走向、结转时点 |
| 抽象 | 新规对行业影响深远 | 说出对哪类主体、哪个环节、什么金额量级的影响 |
| 骑墙 | 应结合具体情况判断 | 给出判断要素的先后顺序与各自的权重 |
| 空洞 | 需要加强管理与监督 | 说出谁在什么时候检查什么、不合规的后果是什么 |

合格的结论长这样（同一个题目的对照）：

> 研究开发项目的支出应区分研究与开发阶段：研究阶段支出于发生时计入「研发支出——费用化支出」；开发阶段支出按是否满足资本化条件分别计入费用化支出或资本化支出。期末费用化支出转入「研发费用」，资本化支出转入「开发支出」；项目达到预定用途形成无形资产的，从「开发支出」结转「无形资产」；过程中形成的样机、样品满足资产确认条件的，按其对应支出从「开发支出」结转「固定资产」「库存商品」等科目。

它合格在三点：有**区分标准**（阶段划分、资本化条件）、有**科目走向**（谁转到谁）、有**边界**（"满足资产确认条件的"）。

### 结论必须写清适用边界（`claim_boundary`）

研究性文章的结论都有前提。边界写三样：**适用范围**（哪些主体/交易/期间）、**例外情形**（哪些情况不适用）、**不确定性**（哪些点现有依据不足、只能给倾向性意见）。边界不写，读者会把它当普适规则用，那是文章最危险的地方。

### 结论不得违反的两个禁令

1. **不得与核心问题脱节**：结论要正面回答 `question` 里问的那件事。
2. **不得穿翻案腔**："不是 A 而是 B""看似 A 实则 B""真正的关键在于"这类先立误解再抬价的句式，在研究性文章里尤其刺眼——同行一眼能看出你没读原文。判断从正面下，依据放在旁边。完整禁令见 `Write/references/a5-draft/revision-protocol.md`。

## 六、`thesis.json` 字段全表

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 是 | 工作标题，可在 A5 定稿时改；不写成问句也能接受，但要能看出对象 |
| `category` | 是 | `政策解读` / `理论分析` / `案例分析` / `操作指引` |
| `discipline` | 是 | `财务` / `税务` / `法律` / `金融` / `经济` |
| `field` | 是 | 研究领域，二级学科或业务条线 |
| `object` | 是 | 研究对象，可指认的名词短语 |
| `question` | 是 | 核心问题，一个问句，带限定条件 |
| `purpose` | 是 | 读者能拿去做什么（动作） |
| `significance` | 是 | 至少两类主体各自得到什么 |
| `claim` | 是 | 研究结论，具体、可执行或可反驳 |
| `claim_boundary` | 是 | 适用范围 + 例外 + 不确定性 |
| `subclaims` | 否 | 分论点的 id 与一句话，A2 用它做 `claim_ref` 的回指目标 |
| `series` | 否 | 系列名与序号，A4 的系列冲突检查用它 |

## 七、`check` 的判据（机器能查的部分）

`thesis_check.py check` 只判**形状**，判不了思想。它查这些：

- **ERROR**：必填字段缺失或空串；`category` / `discipline` 不在枚举内；`question` 不是问句形态；`claim` 与 `question` 逐字相同；`claim` 少于 40 字；`claim` 命中空洞评价词或翻案腔句式；`claim_boundary` 少于 15 字；`significance` 里认不出两类主体。
- **WARNING**：`claim` 没有出现任何条件/范围标记（"当…时""满足…条件""限于""不适用""区分""除外"）；`object` 超过 30 字（八成是塞了一句话）；`subclaims` 少于 2 个（分论点拆不开，说明结论还不够具体）。
- WARNING 需要人工判断，但**连 WARNING 都不肯看就往下走，A2 一定拆不出章节**。

退出码：`0` 无 ERROR；`1` 有 ERROR；`2` 用法错误或文件不存在。

## 八、出口

`thesis_check.py check thesis.json` 退出码 0，且人工确认过 WARNING。之后进 `Write/references/a2-structure/`。

改判据要同步 `tests/test_a_track_gates.py`，并跑 `python tests/run_all.py`。
