# 素材归一化 —— 万物先转 Markdown，再进写作流程

Write 写作流程接受 Markdown 素材。任何非 Markdown 输入（docx / pdf / 纯文本 / 网页富文本）先按本文件转成 Markdown 草稿，**转换只整理结构，不得增删改写原文实质内容**。

## 输入类型判定

| 输入 | 判定 | 处理 |
|---|---|---|
| Markdown | `.md` 或含 `#`/`![]()` 标记 | 直接进写作 |
| Word | `.docx` | `scripts/extract_docx.py 文章.docx -o 文章.md`（零依赖：标题→`#`、粗体→`**`、下划线→`<u>`、列表→`- `、图片解包到 `images/`、表格→Markdown 表格） |
| PDF | `.pdf` | Read 分页读取 + 清噪：删页眉页脚与纯页码行；行尾无句末标点且下行为中文/小写续接 → 合并硬断行；图位置留 `【配图：原 PDF 第 N 页图】` 占位 |
| 纯文本 | `.txt` 或粘贴大段文字 | 语义推断结构：短行（≤20 字、无句末标点、前后空行）且带序号（一、/1./第X章）判标题；无标题时按语义切 3–6 块自拟 ≤12 字章节标题并**明确告知用户标题是自拟的** |
| 网页/富文本 | HTML 残留 | `<h1-6>`→`#`、`<strong>`→`**`、`<img>`→`![](src)`、`<li>`→`- `、`<blockquote>`→`> `；样式属性与剪存工具元信息块剔除 |

## 结构确认（默认必做）

归一化完成后、写作前，把推断结果给用户扫一眼：

> 识别出 N 个章节：01 xxx / 02 xxx / …（其中第 3 个标题是我起的）。图片 M 张。结构对吗？

结构错了排出来全错——这一步花 10 秒，拦住的是整篇返工。

## 与 FastERP 系列的关系

- 教程台账（xlsx）、写作纪律文档（docx）、历史文章（md/html）是主要素材来源：xlsx 台账直接读数据列；docx 母本用 `extract_docx.py`；历史文章可复读 `../Read/` 提取的 Markdown。
- 素材中的代码片段必须与 FastERP 仓库源码逐行一致（见 Write 写作纪律），转换过程中代码块原样保留、不"全角化"。
