# A3 素材：按章节派单、逐条回填、核实到来源

A3 的唯一交付物是 `materials.json`，出口判据是**每一节的材料数达门槛、每条材料都有来源、没有一条停在 `pending`、推断类材料不承担结论**。

研究性专业文章的素材不是"例子"，是**依据**。同行读你的文章，第一反应是"这说法出自哪"。依据不够或来路不清，结论就悬在空中——再漂亮的论证也救不回来。

```bash
python Write/references/a3-materials/scripts/material_ledger.py init --outline outline.json -o materials.json
python Write/references/a3-materials/scripts/material_ledger.py check materials.json --outline outline.json
python Write/references/a3-materials/scripts/material_ledger.py report materials.json
```

`init --outline` 按 `outline.json` 的每一节生成派单骨架，`evidence_kinds` 会变成该节的"待办清单"。

## 一、材料门槛（先于成文，不是成文后补）

**一件材料 = 一条能指回出处的具体依据**。概括性的类别不算，同义改写不算，常识推演不算，模型临时想出的"例如某企业"更不算。

门槛按目标字数折算，**每 240 字至少一件有来路的材料**：

| 目标字数 | 材料下限 |
|---|---|
| 1200 | 5 |
| 2000 | 9 |
| 3000 | 13 |
| 5000 | 21 |

少于下限不许开写。目标字数、用户催促、期限都不能把材料变多。材料不足只有三条路：

1. **能查的先查**。本领域有公开可查的准则、解释、应用指南、裁判文书、统计数据、部委口径、学术文献。研究完重新计数。
2. **一次问完最多三个问题**，且问完不同时交稿。
3. **缩小题目**。把"研发支出的会计处理"缩到"研发过程形成样品的结转"，材料需求立刻下降。缩到材料够为止，宁可明显短于目标字数，也不能用假例子和重复解释填满。

## 二、五类来源身份（`source_type`）

这条直接决定材料能不能承担结论。每条材料必须标一个身份：

| `source_type` | 含义 | 能否直接支撑结论 |
|---|---|---|
| `一手事实` | 准则/法条/司法解释原文、部委公告、裁判文书全文、官方统计、上市公司年报原文 | 能 |
| `当事人自述` | 企业公告中的说明、访谈、监管答复、会议纪要 | 能，但须写明"据该公司公告" |
| `二手概括` | 媒体报道、教材、他人论文转述、行业评论 | 能，但须写明是谁的概括；与一手冲突时以一手为准 |
| `作者推断` | 你从材料推出来的判断 | **不能单独支撑结论**，只能作论证桥；正文要留出"据此推断"的痕迹 |
| `未核实` | 记不清、找不到原文、口径不明 | **不得进正文**，只能留在台账里等核实 |

`check` 的硬规矩：`作者推断` 不能承担全篇唯一的支撑；`未核实` 出现在任何一节即 FAIL。

## 三、来源优先级

同一件事有多份材料时，按这个顺序取：

1. **规则文本**：准则、法条、司法解释、部委规章原文
2. **官方解释**：应用指南、案例解析、监管问答、征管口径
3. **裁判与执法**：判决书、处罚决定书、稽查案例（看说理部分，不只看结论）
4. **一手数据**：年报、统计年鉴、交易所问询回复
5. **学术文献**：期刊论文、专著（用它看争点与不同观点，不当作规则依据）
6. **媒体报道**：只能用来发现线索，用之前必须回溯到上面任一层

来源之间冲突时，**不能挑最适合故事的那一条写死**。写清分歧双方各自主张什么、依据是什么，再说你更信哪一种及为什么。这是研究性文章的加分项，回避冲突才是减分项。

## 四、材料必须落到章节（`section`）

`materials.json` 的每条材料都要有 `section`，指向 `outline.json` 的节 id。这是"按清单搜集并回填"的机械部分：

- 某节材料数低于该节应摊到的门槛 → `check` 报 WARNING（这一节多半会写空）。
- 某节材料数为 0 → `check` 报 ERROR（这一节根本不该存在，回 A2 删掉或改结构）。
- 有材料但没有任何节引用 → `check` 报 WARNING（搜了一堆用不上，说明 A2 的结构没想清楚）。

## 五、`materials.json` 字段全表

```json
{
  "thesis_ref": "thesis.json",
  "outline_ref": "outline.json",
  "target_words": 3000,
  "items": [
    {
      "id": "m01",
      "section": "s1",
      "claim": "研发支出须区分研究阶段与开发阶段",
      "quote": "研究阶段的支出，于发生时计入当期损益",
      "source": "《企业会计准则第6号——无形资产》第八条",
      "source_type": "一手事实",
      "locator": "第八条",
      "verified_at": "2026-11-03",
      "status": "done",
      "note": ""
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `items[].id` | 是 | `m01`、`m02`… 唯一 |
| `items[].section` | 是 | 支撑 `outline.json` 的哪一节 |
| `items[].claim` | 是 | 这条材料用来证明什么（一句话，A4 会把它变成证据节点） |
| `items[].quote` | 否 | 原文摘录；引用原文时必填，且正文要原样使用或明确改写 |
| `items[].source` | 是 | 出处：文件全名 + 条款号 / 案号 / 报告名与页码 / 文献题名 |
| `items[].source_type` | 是 | 五类之一 |
| `items[].locator` | 否 | 定位：条款号、页码、段落位置、URL |
| `items[].verified_at` | 是 | 你最后一次核对原文的日期（`YYYY-MM-DD`）。政策与口径会变，日期是它的保质期标记 |
| `items[].status` | 是 | `done` / `pending` / `dropped`。`pending` 是待补，出口前必须清零 |
| `items[].note` | 否 | 口径冲突、版本差异、适用范围限制等要提醒正文注意的事 |

**`verified_at` 为什么必填**：财税法律口径按年变（税率、扣除标准、准则修订、司法解释更新）。一条三年前的核对日期，等于告诉读者"这条我没再看"。凡涉及金额门槛、税率、报送期限、准则条号的，写作前重新核对一次。

## 六、代码与数据作为材料

技术型论据（SQL、脚本、计算过程）同样算材料，但要满足：来自真实环境、可复现、正文给出关键片段与路径。编造的代码比编造的数字更容易被识破，而且后果更严重——同行会照着跑。

数据材料必须核四件事：**时间、单位、样本、口径**。百分比与百分点分开写。数字后面要说明它让谁多花多少时间、少付多少钱、多承担多少风险，否则数字只是装饰。

## 七、`check` 的判据

- **ERROR**：`items` 为空；必填字段缺失；`source_type` 不在五类枚举内；`status` 不在三值内；`status=pending`（出口前必须清零）；`source_type=未核实`；`section` 指向 `outline.json` 里不存在的节；某节材料数为 0；材料总数低于 `ceil(target_words/240)`；全篇没有一条 `一手事实`（研究性文章不带一条规则原文，结论就没有落点）；`作者推断` 占全部材料 ≥ 50%。
- **WARNING**：某节材料数低于该节按字数摊到的门槛；有材料未被任何节引用（孤儿材料）；某节只有 `二手概括` 没有一手；`verified_at` 早于一年前（口径可能已变）；`quote` 为空但 `source_type=一手事实`（引规则原文不摘原句，多半没查原文）。

## 八、出口

`material_ledger.py check materials.json --outline outline.json` 退出码 0，`pending` 清零。之后进 `Write/references/a4-logic/`。

改判据要同步 `tests/test_a_track_gates.py`，并跑 `python tests/run_all.py`。
