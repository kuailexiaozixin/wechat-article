# A5 改稿协议：成稿禁令与七遍改稿

初稿写完不算完。这份文档管两件事：**哪些句子绝对不能出现在成稿里**（第八节禁令的判据源，`check_prose.py` 的硬禁词表必须与之逐字一致），以及**按什么顺序改**。

## 一、七遍改稿（按序执行，不参与第一稿生成）

改稿先救人：**保护已经活着的地方**，再拆模型摆的姿势。每一遍只做一件事，做完再进下一遍。

### 第一遍：看谁在说

- 作者凭什么知道这件事？哪处看得出真在意？
- 哪个判断有材料托着（回 A3 的台账对一遍）？
- **哪几段换一个模型也能原样写出来**——优先处理。补信息的来路与取舍；没东西可补就删。
- 不要用"我觉得""说真的"修复匿名感。声音来自取舍，不来自口头禅。

### 第二遍：看推进

- 给每段标主要作用（立论/举证/反驳/举例/过渡/结论）。连续几段做同一件事就拖。
- 后段只把前段换成另一套说法 → 合并或删除。
- 给每段写不公开的材料出处（对应 A3 的 `materials.json`）；写不出"这是进一步解释"的段落删掉。
- **压缩试验**：删三分之一后几乎没变，就是在注水，保留删短版。

### 第三遍：拆表演性中文

- **假深刻**：单独截图好看、放回正文没增量。
- **假具体**：无来源的精确时间、天气、神态、房间摆设。专业文章里的假具体通常是"某企业""有数据显示"——查不到就是编的。
- **假口语**：老铁、兄弟们、咱就是说。
- **抽象名词连续出现**时问一句：谁做了什么？
- **比喻换场**：短距离连着三套借喻，全部还原本义。

### 第四遍：听中文

- 主干早点来（圈出「……的，是……」「更……的是」这类句式）。
- 前一句把什么交给了后一句？换对象只靠「这/它」连接会认错人。
- 停顿有轻重：连续短句像敲桌子就合并。
- 动作后面少解释。
- 单双音节别打架（买/购买、看/观察）。
- 成语典故删掉更自然就删。

### 第五遍：清禁令

按**动作**查翻案腔，不只按字面（见第二节）。跑 `check_prose.py`，失败项清零。

### 第六遍：核现实与条文

- 时间、数字、主体身份、引语、因果链、第一人称动作。
- **条款号与文字逐字对原文**（这是专业文章最高频的错误来源：条号写错、把旧版条文当现行、把征求意见稿当正式稿）。
- 核验记录留在后台，不进正文。

### 第七遍：查结尾

- 最后两段分别删掉再读，删掉更有力就提前结束。
- 末段重新摘要全文的，先删掉。
- 正文没持续处理大尺度问题，结尾就别升华（搜「时代/文明/未来/世界/所有人/新征程」）。
- 开头那个具体问题在结尾回来前，确认含义已经变了。

### 最后冷读

回答四个问题：

1. 哪里让我相信作者确实读过这些文件？
2. 哪里让我愿意继续读？
3. 哪一段像人在处理一个问题，哪一段像模型在完成任务？
4. 哪句话说得比材料大？文章在哪一句已经结束？

## 二、翻案腔：按动作识别，不按字面

翻案腔是**先立一个读者没有的误解，再推翻它来抬价**。换一套字继续做同一个动作，仍然命中。

已知外衣（`check_prose.py` 逐条匹配）：

- 不是 A 而是 B ／ 并非 A 而是 B ／ 不在于 A 而在于 B
- 与其说 A 不如说 B
- 表面 A 实际 B ／ 看似 A 实则 B
- 不是 A，是 B ／ 不是 A。而是 B
- 你以为 A 其实 B
- 回头才发现 ／ 说到底 ／ 答案恰恰相反
- A 不重要，重要的是 B
- 真正的问题 ／ 真正的关键

**为什么在专业文章里尤其刺眼**：同行读原文，一旦发现你立的那个"误解"根本没人这么想，整篇的可信度就没了。而这类句式常常伴随对规则的简化——为了制造反转，把有条文依据的争议写成"大家都搞错了"。

**唯一正确的改法**：找到这句话原本想下的判断，**从正面用普通句子说出来**，依据放在旁边。不许找另一种漂亮句式替换——换皮的翻案腔仍然是翻案腔。

专业文章允许出现一次**自我修正**（"起初我以为…后来看到第九条第二款…"），前提是文章真的用材料走过了这段路。

## 三、句式禁令

| 禁令 | 说明 |
|---|---|
| 三项以上同构排比 | 两项为限，第三项换说法或删掉 |
| 动词名词化 | 「完成了对流程的优化」→「把流程改顺了」 |
| **破折号** | `—`、`——`、`–` 全部不用 |
| **提示性冒号** | 「一句话总结：」「核心是：」「关键在于：」禁止。冒号只允许引出人物直接原话；网址、代码、机器字段除外 |
| 洞察路标 | 「更微妙的是」「还有一层」「只说对了一半」「值得注意的是」「需要指出的是」「从某种意义上说」不作段落路标（说本义时不受影响） |
| 抽象名词配抒情动词 | 「时间不会保管细节」「岁月不会磨平什么」 |
| 每段结尾金句 | 普通段落用普通句子结束 |
| 自造术语加引号 | 有名字就直说，没名字不要发明口号 |

不用：「说白了」「说穿了」「先说结论」。

「不只……还……」是正常递进可以用；出现在翻案位置给下文抬价时按翻案腔处理。

## 四、黑话清单

### 绝对禁词（`check_prose.py` FAIL）

赋能、抓手、商业闭环、价值闭环、能力沉淀、拉通、底层逻辑、顶层设计、认知跃迁、价值释放、能力建设、降本增效、内容矩阵、全链路、组合拳、打开想象空间、结构性机会、关键命题、深层逻辑、技术底座、公共底座、技术主权、单点风险、主脊柱、材料锚点、认知增量、迭代闭环。

### 语境词（本义保留，抬价改写）

沉淀、颗粒度、对齐、协同、链路、生态位、心智、范式、方法论、核心变量、打法、想象空间、闭环、不丢。

### 抒情词（写具体事物是好词，给抽象概念穿衣服时删）

安放、抵达、微光、褶皱、丰盈、滚烫、轻盈、赤裸、剥开、锋利、坚硬、柔软。

### 非虚构不用借喻

用水库、抽屉、温度、死亡、坍塌、浪潮、钥匙、底座等借喻包装抽象概念。

**原话命中禁令时改成转述或省略，不靠引号保留。**

## 五、专业文章特有的四种病

这四种不在通用禁令里，但研究性专业文章最常见，出现即为硬伤：

| 病 | 症状 | 改法 |
|---|---|---|
| **条款虚指** | 「根据相关规定」「有关文件明确要求」 | 写出文件全名与条款号；查不到就删掉这句 |
| **效力错配** | 用部门规范性文件推出"应当"，或把征求意见稿当生效文本 | 回 A3 核 `source_type` 与效力层级，强度按第五节降级 |
| **强度漂移** | 同一段里"应当""可以""建议"混用 | 一条判断一个强度，按 A5 第五节的分级表定 |
| **个案泛化** | 一个案例或一家企业的做法推成行业通例 | 写明样本范围；只在材料支持的分量上说话 |

## 六、AI 味的词汇层与结构层

完整的六类词汇黑名单与十四种句式反例→正例在 `de-ai-playbook.md`。这里只留判据：

- **权威与让步腔**（众所周知、不可否认、毋庸置疑、事实上、实际上）：共识不需要宣布，直接陈述；有争议就写清分歧双方与各自依据。
- **万能开头**（随着…的发展、在…的背景下、近年来…日益）：从一条具体条文、一次具体处理、一个具体数字开始。
- **万能结尾**（让我们、拭目以待、揭开新篇章、迈上新台阶、保驾护航）：事情讲完就停。
- **结构层六特征**：均衡三段式、总分总固定、面面俱到、知识展览、观点推演繁殖、注水。破解办法见 `de-ai-playbook.md` 第四节。

## 七、事实边界（专业文章的底线）

- **材料五类身份**（与 A3 的 `source_type` 一一对应）：一手事实 / 当事人自述 / 二手概括 / 作者推断 / 未核实。
- **正文只保留读者需要的归属**：确定事实直接写；自述、回忆与争议说法第一次出现时说明是谁的说法；未知且影响结论时正文交代一次。
- **「公开资料显示」「目前无法确认」连续出现**，说明核验笔记漏进了正文。
- **用户经历不能代写**：「看见」不能扩成「试过」；一张截图不能补完整流程；记不清原话就写大意或请对方确认。需要个人材料最多问三句。
- **历史与沿革分三件事**：先后（按时间发生）≠ 因果（前者促成后者）≠ 动机（因某个想法行动）。只有先后证据时不能用"于是""这让他决定"补因果。
- **判断要有边界**：先把反方最有力的理由讲准确，再说更相信哪种解释；建议带成本与适用条件。
- **来源交付**：全靠公开材料的文章，文末列对结论重要的少数来源。

## 八、词表维护

`check_prose.py` 的 `HARD_JARGON` / `HARD_STOPS` / 翻案句式，与 `Write/references/b3-acceptance/scripts/validate_wx_html.py` 的 `BANNED_WORDS` / `AI_FLAVOR_PHRASES`，**三处必须同一轮更新**。

规则：

1. 新增词前先跑一遍近期成稿，确认无误报再入库。
2. 语境词（本义用法常见）一律进 WARNING 或人工层，不进 ERROR。
3. 本文件第二节、第四节的清单改动，必须在同一轮同步改脚本，否则文档与判据漂移。`tests/test_a_track_gates.py` 会核对三处词表的关键条目一致。

## 九、检查顺序

```
初稿（A1-A4 四张清单在手）
  → 七遍改稿（本文件第一节）
  → check_prose.py 清零
  → 冷读四问
  → B 轨道（B1 配图 → B2 排版 → B3 验收 → B4 推送 → B5 回读）
```

B 轨道里的 `validate_wx_html.py` 会再查一遍 HTML 层的禁用词与 AI 味启发式——**两道都跑，不是重复**：`check_prose` 管纯文本的散文硬禁令，`validate` 管 HTML 里的微信兼容红线与形状启发式。
