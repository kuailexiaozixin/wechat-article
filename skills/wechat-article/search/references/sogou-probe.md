# 搜狗微信搜索实测记录（Search 的论证来源）

这一份只回答两件事：**每条参数口径的依据是哪个样本、每一格「未判定」缺的是什么证据**。
命令、输出字段、退出码与处置动作一律在 `search/SKILL.md`，两边不重复。
下面每个数字都是 2026-10-17 本机对 `weixin.sogou.com` 的返回值；换机、换网、隔期之后要先复采再引用。

## 1. 判定纪律（这条比表格里任何一格都重要）

本机 IP 在 2026-10-17 那一轮 26 个参数用例里有 10 个最终落到 `antispider`；另一次复采起手连续四次请求（含重试）全部被拦，脚本按熔断停手。同一个参数重试之间也会一次成、一次废，成功与失败和参数没有稳定对应——**单发请求拿到一次 BLOCK 不能判成「该参数不可用」**，只能判「未判定」。表内标 **未判定** 的行就是按这条纪律留空的：宁可缺一格，不要把抽样抖动写成结论。要补上任何一格，需要同一 URL 三试内稳定复现同一形态，且与不带该参数的对照请求能区分开。

## 2. 逐条结论的样本明细

| 结论项 | 采到的样本 |
|---|---|
| `s_from`/`_sug_` 可省 | 去掉这两个参数同样返回 10 条 |
| 翻页上限 10 页 | `page=10` 仍出结果；`page=11`/`12` 返回无结果容器，且两次页面长度逐字节相同（10488） |
| 服务端时间筛选不可用 | `tsn=1`/`2`/`3`/`4` 四次请求全部 302 回首页。脚本因此一个时间参数都不发 |
| 同页时间戳非严格倒序 | 关键词「税务」切片 10 条里 4 处「后一条比前一条新」、日期跨度约 0.3 天；关键词「公众号排版」page=1 十条里 3 处倒序（位置 4/7/8），首条 2020-10-08、末条 2017-06-22，跨度 1204 天。同一关键词隔 9 秒两次抓 page=1，标题序列逐条一致、页面长度逐字节相同，所以倒序来自搜狗的收录排序，与抓取时刻无关 |
| `type=1` 搜公众号 | 两轮实测均返回空的结果容器（本轮页面长度 10196），拿不到账号列表 |
| 检索语法 | `OR`、`-排除词`、`intitle:` 都能返回结果页；`"精确短语"`、`site:` 未判定。「返回结果页」不等于「语法生效」——判生效要比对带与不带该语法两次请求的标题集合，本轮没做完这组对照 |
| 每页条数固定 10 | 结构判定用的是四类节点各 10（见下）；`num=20`/`n=20` 是否放大每页条数未判定，该轮请求撞反爬 |
| 结果节点形状 | 真实切片 box / `h3>a` / `timeConvert` / `span.all-time-y2` 均为 10，而 `/link?url=` 链接有 20 条（标题之外还有第二跳），所以链接数不参与结构判定；标题在 `h3 > a`（内含 `<em>` 高亮，取值后去标签），公众号名在 `span.all-time-y2`，时间由页内 `document.write(timeConvert('<unix>'))` 给出 |
| 正常页的量级 | 本机两张 page=1 切片逐字节相同，均 31243 字符。读满 `MAX_BODY_BYTES`（4MB）即说明拿到的根本不是结果页；按字节收口是因为 25 秒超时管不住「慢而不断」的响应 |

## 3. 为什么不做到页去重、也不做「本页变旧就停」

早停：单页内日期跨度实测能到三年（见上表「同页时间戳非严格倒序」），任何「页最小时间戳 < 窗口下界就停」的阈值都会把窗内文章切掉；而定阈值需要多页样本，本机当时取不到。

去重：`-n 30 --pages 3` 那轮只拿到 page=1，page=2 命中 `antispider`（5266 字符；当轮 `--dump` 落在系统临时目录，随后按临时文件清掉了，仓库内没有这两份样本，上面的字数只到「本机当次返回值」为止）。跨页重复率因此没有量过，脚本就原样拼接（`raw.extend(got)`），`-n` 数的是交付条数。做去重会同时改动 `-n` 的语义与结构哨兵的比对基数，不能凭猜加。

**复采这两格的方法**：把 `--dump` 指到 `tests/fixtures/` 下（而不是临时目录），样本进了仓库才算可复验依据；同一关键词连翻 3 页，比对标题集合与每页时间戳序列。

## 4. 首页预热到底有没有用

搜索前置一次 `weixin.sogou.com` 首页请求，只为拿 `ABTEST`/`SUID` 等种子 cookie。**别把这条当成已证的抗拦截手段**：早期一轮里空 cookie 直查失败过，而本轮 A/B 里「不做预热」两次都拿到 10 条结果、「首页预热」一次成一次被拦——五个样本判不出预热有没有用。保留首页引导的理由只有「多 1 次请求、没有下行风险」。

**预热入口不换**：第三方实现用的 `v.sogou.com/v?ie=utf8&query=&p=40030600` 实测属视频频道，只落下 `VIDEO_DEBUG`/`wuid`，不带微信频道要的种子 cookie，紧随其后的搜索正好命中 `antispider`；两个入口谁更抗拦截本轮没有分出（不做预热也成功过两次），但视频频道 cookie 对微信频道没有作用路径，所以保留首页引导。

## 5. 拦截页长什么样

脚本侧能确证的只有标记（`antispider`、`wappoc_appmsgcaptcha`、"环境异常"、"验证码拦截"、`anti.min.css`）。仓库样本 `tests/fixtures/sogou_antispider_sample.html` 里，正文是「当前环境异常，完成验证后即可继续访问」，验证由页面自带的 `static/js/antispider.min.js` 驱动；人工打开该页所见是按顺序点选汉字，不是可提交的文本验证码框。无论哪种，脚本层都没有可自动完成的填写动作，所以命中时唯一正确处置是**停手**：把已拿到的列表结果照常交付，需要继续时由用户在浏览器里人工完成一次验证再跑。

`anti.min.css` 这个标记在该样本里实存（拦截页自带 `static/css/anti.min.css`），在本机两张真实结果页切片里 0 次命中，加进标记集不会把好页面判成拦截（`tests/test_search_parser.py` 第 12 节两个方向都断言）。

## 6. 票据存活时长

还原得到的真实链接里 `timestamp`/`signature` 是当次会话的跳转票据。确切存活时长**未实测**——要跨会话、跨 IP 长时间复采同一张票据才能量出。所以 `search/SKILL.md` 第三节给的两条处置（`resolved_at` 距今不久就立刻交 `read/`、隔了一段时间或换网就作废重取）都不依赖具体时长。

## 7. 未判定清单（七项，各自缺的证据）

| 未判定项 | 缺什么才算判了 |
|---|---|
| `num` / `n` 能否放大每页条数 | 同一关键词带 `num=20` 与不带各三试，比对条目数与四类节点数 |
| `ie=gbk` | 同一关键词两种编码各三试，比对标题集合是否等价 |
| 缺 `type` 参数 | 去掉 `type` 后三试，看是否稳定回到首页或空容器 |
| `ft`/`et`、`ss_st`/`ss_et` 时间参数 | 与 `tsn` 同样本量：三次请求看是否 302 或忽略 |
| `"精确短语"`、`site:` 语法 | 带与不带两次请求的标题集合比对 |
| 跨页重复率 | 连翻 3 页且页面存进仓库（见第 3 节复采方法） |
| 翻页之间日期是否单调 | 同上，需要多页时间戳序列 |

本机 IP 冷却后按第 1 节的判定纪律逐格复采；补上任何一格都要同时回头改 `search/SKILL.md` 第二节那一行的结论。
